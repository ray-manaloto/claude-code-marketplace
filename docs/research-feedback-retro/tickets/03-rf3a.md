# RF3a: Share verified refresh outcome behavior

Spec: [shared outcomes](../specs/03-shared-outcomes.md).
Blocked by: RF1 and RF2's verified contracts and acceptance receipts.
Status: approved local slice; unpublished; prerequisites pending.

## What to build

Share dependency-free receipt/state-transition behavior beside existing coverage
feedback. Synthetic tests exercise accepted state, failure stages and evidence
references without adding another live research transport.

## Acceptance criteria

- [ ] Native failure, invalid output, comparison/runtime failure and recovery outcomes.
- [ ] Separate attempt failure, comparison status and coverage/baseline eligibility.
- [ ] Peer-compatible comparison vocabulary and evidence-before-state semantics.
- [ ] Confined relative evidence references/digests; no private diagnostic bodies or paths in fixtures.
- [ ] Shared checks wired into normal development checks and existing CI entry point.
- [ ] Focused/full checks, original hashes, independent review and applied/reverified retro findings.
- [ ] Small reviewed commit integrated serially; no push, merge or public issue mutation.

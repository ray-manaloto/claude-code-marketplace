# RF1: Preserve accepted history after comparison failure

Spec: [comparison failure](../specs/01-comparison-failure.md).
Blocked by: none semantically. Serialize private application with RF2.
Status: approved local slice; unpublished; implementation pending.

## What to build

Ordinary and proposal comparison failures retain raw evidence and a truthful
failed-stage receipt, return failure, and preserve accepted baseline/history.
Subsequent comparison uses the preserved, uniquely resolved baseline.

## Acceptance criteria

- [ ] First baseline, verified legacy migration and missing/corrupt/ambiguous baseline controls.
- [ ] Search success followed by comparison failure/timeout preserves history/catalog.
- [ ] Subsequent success compares to the previously accepted baseline.
- [ ] Coverage warnings advance observations separately; unverified empties never establish a baseline.
- [ ] Post-cycle exceptions and evidence/state write failures retain truthful incomplete outcomes.
- [ ] Receipt/event/state ordering and evidence digests verified at the runner boundary.
- [ ] Red/green receipts, focused/full checks, independent review and applied/reverified retro findings.
- [ ] Frozen private preimages/postimages; guarded parent application; no borrowed runtime or provider calls.

Private artifacts are applied/verified, never claimed as Git commits. Retain
publication as blocked until the qualified tracker operation exists.

# Research feedback improvement guidance

Follow the approved [shared-guidance specification](specs/03-shared-outcomes.md)
and [RF3b ticket](tickets/04-rf3b.md). The standing sequence is grill-with-docs →
to-spec → to-tickets → implement-spec → retro; apply and verify every actionable
retro finding before acceptance. Reuse inherited skills and existing checks.

The authority owner's `docs/agents/issue-tracker.md` remains the source of authority
in that owner's checkout; it is not present on this integration branch.
The [peer-authority amendment](workflow-authority-amendment.md) is staged for its
owner, not applied authority. Local specs/tickets remain unpublished until the
project's tracker operation qualifies. The [portable workflow](portable-workflow.md)
and [runner setup](../../dev/research_refresh/README.md) share the accepted RF1/RF2
implementation, complete offline controls, configuration examples and lessons.
Local runtime admission, credentials and research state remain separately owned.

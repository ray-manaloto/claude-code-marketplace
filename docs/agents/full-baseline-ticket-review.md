## Findings to fix before publication

1. **The graph has no delivery path from the native core to a Claude plugin user.** The current SessionStart hook installs a pipx tool pinned to the external knowledge-base commit. The native library currently exposes only a reflection probe. A CMake/CPS consumer does not establish how that tool reaches the plugin's confined data directory. Add a measured distribution/install slice with rollback; keep the existing marketplace, plugin and `trackers` contract until parity is proved. Do not preselect signing, hosting, a wheel or a helper process without a prototype.
2. **The first provider tracer is too large and starts from an unspecified external baseline.** Ticket 09 combines bridge placement and generator qualification. Ticket 10 then assumes JSON/transport, typed records and an existing CLI source that are absent here. Separate pinned knowledge-base behavior capture, measured bridge placement, a canonical Issues schema/POD fixture, dependency/transport admission and a CLI extension rule. The existing CLI has only `trackers`; the other six operations are new surfaces, not legacy CLI parity claims.
3. **Plan evidence and execution semantics have missing owners.** Add a GitHub source-at-ref primary-evidence operation, an identity registry distinguishing provider, route, upstream and corpus, plan validation for capabilities/corpora/freshness/budgets, and bounded process/network timeout enforcement. Move immutable attempt artifacts and borrow/cancellation lifetime ahead of broad provider migration. A provider success must remain distinct from a plan coverage verdict.
4. **Native dependencies mistake an unproven LSan repair for an ordinary completed prerequisite.** Task 14c ended with clean LSan timeout and uncommitted evidence. Split the private repair trial, guarded installed-runtime preparation, and promotion. Split admitted-family coverage from LSan coverage so qualified ASan/UBSan/TSan work can proceed. A negative repair result must remain an incomplete required mode; closing an issue with a failed receipt never satisfies the final acceptance gate. Commit and cite the Task 14c closure before a fresh agent starts its successor.
5. **Foundation and final acceptance are ordered incorrectly.** Accepted decisions put the native foundation before product migration, while native acceptance run before new core code becomes stale. Give the foundation its own successful gate before provider migration and rerun native matrix/relocated consumers on the final product at release acceptance. Several original tickets (04, 09, 25, 27, 33, 34) combine work too broad for one fresh context; split behavior from final receipt aggregation.
6. **Host adapter generation and status-aware takeover are underspecified.** Add the thin Claude adapter and generated host bindings from common contracts. Require installed-version receipts for Codex, Antigravity and OpenCode. The standby runbook must check successful prerequisite dispositions, review and matching input identities, not issue closure alone. Keep user-activated sole-writer transfer explicit.
7. **Provider and policy gates need honest test targets.** Discussions are disabled in this repository, so a positive-control target must be chosen before labeling an empty result verified. Current strict-five research remains incomplete; Firecrawl credits and other quotas are blockers, not waived passes. Optional inference requires a no-spend fixture or separately admitted spend. The default read-only/opt-in policy needs a concrete controlled fixture or operation that can prove the denial path.

## Dispositions and limits

The graph was mechanically acyclic, all 34 references resolved, and its stated initial frontier was correct as a graph calculation. That did not establish that every edge was semantically correct or that all five eligible tickets could run concurrently under the one-writer/one-heavy-operation rules.

The reviewers disagreed on whether a failed LSan trial should let final acceptance close with an incomplete mode. The accepted plan says an unresolved required mode remains incomplete, so final acceptance stays blocked until that mode is qualified or the user changes the requirement. Admitted-family coverage can still progress separately. Claims that scratch diagnostics were unadmitted were not established by the bounded review and are not treated as a finding. The current runbook no longer asserts a scratch repair lacking a durable receipt.

The Fable reviews did not rerun native witnesses, inspect all retained raw research evidence, or validate GitHub tracker state. The Codex reviewer inspected documents and Git status, not implementation or hosted acceptance. Source checks in this review confirmed the external pipx pin, SessionStart install, `verbs: trackers` assertion and foundation-only C++ API. All proposed ticket changes remain unpublished pending a revised numbered graph and user approval under the to-tickets workflow.

# Domain docs

This is a single-context repository. Read root `GLOSSARY.md` when present
and relevant ADRs under `docs/adr/` before naming domain concepts or
changing an accepted contract. If either is absent, continue without
treating absence as a defect. Domain modeling creates glossary entries and
ADRs only when a term or durable tradeoff is resolved.

Use glossary terms in specs, tickets, code and tests. Surface any conflict
with `docs/accepted-decisions.md`; that document remains the authoritative
accepted product and build record until a new decision explicitly supersedes
it.

# A11b retrospective — guarded source checkout switch

A11b supplies the mutating half of A11. It accepts an exact A10 plan and
A11a intent, rechecks their bytes and live checkout/remote preimages, records
each phase with exclusive durable journal files, and switches the published
branch from the retained worktree to the source checkout. It refuses replay or
uninspected recovery. This code does not prepare the source environment.

The isolated implementation passed five scratch Git-worktree tests, task
validation, static check, baseline19 and diffcheck. Independent final-byte
cold review passed. Parent integrated the two reviewed Python files and the
11-line named task block; its five scratch tests, task validation (50),
`check`, baseline19 and diffcheck exited 0. At helper publication, no live
switch had occurred. A11 remained partial until a fresh plan/intent was bound to the
published helper, the switch is verified, and the source root is qualified.

The earlier A11a preflight scope defect is covered by the exact production
binding. A11b adds a second live revalidation immediately before detach,
checks the old checkout after detach, checks source and remote again before
switch, and verifies both checkouts afterward. Its recovery path only
reattaches the old branch when both preserved preimages still match; other
failures require journal inspection. The deliberately retained dirty and
untracked content is never reset or deleted.

Navigation is through `checkout:switch-guarded` and `test:checkout-switch`.
The five scratch cases exercise success, preservation, drift and interrupted
recovery, so an extra no-op gate or coding-standard change is unwarranted.
This three-file atomic unit is about 341 added lines, slightly above the
approximate 300-line guide; it is smaller than combining source preparation
and qualification with the switch. Full Claude/container acceptance remains
a separate gate.

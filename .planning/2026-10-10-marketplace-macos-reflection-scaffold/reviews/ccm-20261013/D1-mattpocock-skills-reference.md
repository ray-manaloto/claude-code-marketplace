## 1. Invocation model

- **Two kinds of skill, one axis: who can reach it.** User-invoked = `disable-model-invocation: true` (Claude Code) plus `policy.allow_implicit_invocation: false` in `agents/openai.yaml` (Codex); reachable only by the human typing its name; description is human-facing. Model-invoked = default; reachable by model or user; description carries trigger phrasing (`P/.agents/invocation.md:5-6`). The two flags must stay in sync (`:10`). Verified: the same 16 skills carry both flags (grep of `SKILL.md` and `openai.yaml`).
- **The invariant.** "Each harness excludes a user-invoked skill from the model's reach in its own way, so nothing but the human can fire it: no other skill can. A user-invoked skill may invoke model-invoked skills, but it can never reach another user-invoked skill." (`invocation.md:8`; restated `README.md:211`, `SKILL-MECHANICS.md:10,23`).
- **Consequence for an orchestrating Claude session.** A session cannot type slash commands, so every user-invoked skill (`ask-matt`, `grill-with-docs`, `grill-me`, `to-spec`, `to-tickets`, `implement`, `implement-spec`, `triage`, `wayfinder`, `retro`, `setup-matt-pocock-skills`, `improve-codebase-architecture`, `handoff`, `teach`, `to-questionnaire`, `wait-what`) is unreachable from inside a skill or from the model's own initiative. The docs say it plainly for `implement`: "Wherever ask-matt or to-tickets says 'then /implement per ticket', that is an instruction to you, not something the agent will do unprompted" (`D/implement:9`). Preconditions on user-invoked skills must be phrased as "tell the user to run `/setup-matt-pocock-skills`", never a Skill-tool call (`invocation.md:22`). Known harness bug: user-invoked skills are absent from the injected skill list, so the agent reports them "not installed"; `.claude-plugin/plugin.json` is the authority (`D/ask-matt:57`).
- **Dependencies.** Expressed only as "Call the Skill tool with "<name>"", one skill per call ("Call the Skill tool twice, for "grilling" and "domain-modeling""), never bare `/name` prose or cross-folder file links; router prose (`ask-matt`, READMEs) may use `/name` as labels (`invocation.md:16-20`). Reading `GLOSSARY.md` for vocabulary is a prose pointer, not `domain-modeling` (`:24-25`).
- **One unbroken window.** "Keep steps 1–3 in one unbroken context window (don't compact or clear until after `/to-tickets`) so the grilling, spec, and tickets all build on the same thinking. Each `/implement` then starts fresh, working from the ticket. Run `/retro` in the session it's looking back on, before you clear; after clearing, point it at that session's log instead." (`S/ask-matt:38`). Per-ticket: "`/implement` per ticket, `/clear`ing context between each one" (`:26`); `implement-spec` runs the whole graph in one orchestrating session, started after a clear (`D/implement-spec:40`).
- **Smart zone.** ~150k tokens; if a session nears it before `/to-tickets`, `/compact` at the nearest phase boundary rather than pushing on degraded (`S/ask-matt:40`; `PHASE-BOUNDARIES.md:21`). Compacting mid-phase loses the thread (`PHASE-BOUNDARIES.md:5`).
- **Codex metadata** exists for every skill (`agents/openai.yaml`), so the promoted set is dual-harness (`invocation.md:10`; ADR 0002 updates 2026-10-07/08).
